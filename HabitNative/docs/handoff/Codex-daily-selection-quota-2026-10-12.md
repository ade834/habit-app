# 今日选择名额与星标交接（2026-10-12）

用户要求：已完成的单个任务仍计入当天新建选择名额；星标可点按；数据库记录与页面计数一致。
补充：继续选择按钮只在当天已选加已完成的任务总数不足 3 个时显示。

当前问题：`habit_selections.active_on` 只表示当前选择，重新保存时可能清空旧项；已完成任务从待做列表移除。计数和数据库校验未持久记录“今天已用过的普通名额”。卡片星标使用零距离拖动手势，易与卡片集滑动手势冲突。

接口计划：在原生私有 SQLite 增加 `daily_selection_records(habit_id, local_date, counts_regular)`；完成任务后保留当天选择记录，未完成且取消的记录释放名额。`HabitSelectionSnapshot` 增加已完成普通任务 ID 集合，页面计数与保存校验均按该集合和当前普通选择去重计算。旧记录根据当天 `habit_logs` 和积分记录迁入。星标改成直接点按的按钮，保留首次选择禁设星标和阶段上限。

影响文件：`NativeDatabase.swift`、`SharedHabitSelectionStore.swift`、`Goal.swift`（共享数据边界）；`ContentView.swift`、`TodayComponents.swift`（Codex 独占界面）。Garden 和 GrowthView 不变。用户本轮明确要求数据库规则与同步显示；上述数据层属于此前已确认由 Codex 维护的原生迁移接口。另一方如需更改共享边界，应先核对本记录。

验证：原生数据库升级为 schema 13；17 Pro 原有今日完成任务在升级后出现在 2/3 计数。隔离数据库验证了完成后换选、星标写入、超过三个普通名额时拒绝保存，以及未完成取消后释放名额。界面上点按星标可见星标 1/1，返回撤销未确认变更。

补充触摸修复：辅助功能点按可用，但真实屏幕坐标点击最初无效。星标按钮原本嵌在缩放、位移的卡片中，图标与命中区域不一致。现把按钮作为卡片集最高层的独立控件，按相同卡片位置计算坐标。17 Pro 上直接点击主卡星标两次，计数在 0/1 → 1/1 → 0/1 之间变化；上下滑动仍能翻卡。测试没有确认保存。
