## 结论与目标

本次不是在现有 Flutter 页面上继续修样式，也不是根据文字重新设计一套原生页面。

目标是将已确认的网页原型逐屏复刻为原生 iOS SwiftUI 页面，并在视觉和交互验收通过后，用 SwiftUI 页面替换当前 Flutter UI。现有 Flutter 工程保留为习惯规则、数据模型和业务验收参考，不能直接将其 Widget 代码转换为 SwiftUI。

## 不能接受的实现方式

1. 不根据文字重新发明布局、配色、标题层级或导航结构。
2. 不把网页直接嵌进 `WKWebView` 作为最终实现；它只能用于临时对照，不能当成原生最终页。
3. 不在当前 Flutter 工程内逐个修 UI 后再迁移；这会重复做两次界面工作。
4. 不一次性迁移 H1–H12、Drift、复盘、旅行、通知等所有模块。
5. 不用“差不多”作为完成标准。每个状态都要与网页母版同尺寸并排截图验收。

## 现有网页状态机：必须一一对应

网页中已有以下状态，不要另外发明第二套状态：

```swift
enum TodayMode {
    case homeUnselected       // S1
    case browsingDeck         // S2 / S3
    case homeSelected         // S4
    case executing(goalID: String) // S5
}

struct TodayGoalState {
    var mode: TodayMode
    var focusedGoalID: String
    var selectedGoalIDs: Set<String> // 最大 3
    var homeSelectedIndex: Int
}
```

状态转换：

```text
homeUnselected --点首页预览--> browsingDeck
browsingDeck --上/下翻阅--> browsingDeck（焦点变化）
browsingDeck --右滑卡片--> browsingDeck（选择变化，最多三项）
browsingDeck --确定选择--> homeSelected
homeSelected --左右滑动--> homeSelected（已选卡切换）
homeSelected --开始目标--> executing(goalID)
executing --提交--> homeSelected（先显示提交成功反馈；真实完成逻辑后接）
browsingDeck --点标题--> homeUnselected
```

### 关键实现要求

- `LiquidBackgroundView`：用 `Canvas`、`TimelineView` 或低频 `KeyframeAnimator` 绘制两个不规则主光体与两个小光点；不能因视图重绘或后台恢复而停止。主色面积保持橙色 : 紫红色约 6 : 4，并在灰色底上交融。
- `GoalDeckCardShape`：采用原生 `Shape` / `Path` 生成上部圆角矩形和向下收的斜边尾部。不要照搬网页 `clip-path: polygon()` 的硬折点；斜边必须接入下一张卡片圆角内，尾端在下一张卡上缘前约 2px 渐隐。
- `GoalDeckView`：七张卡片始终存在，不在翻页中即时增删。用连续 `focusedPosition: CGFloat` 驱动每张卡的 `y`、露出高度、层级、缩放和透明度；上下翻动以相邻卡片连续移动的方式完成。
- 主阅读位固定为第三位置。第 4、5 位置露出高度递减更明显；第一、第二与末尾两张必须保留最小可见安全范围，不能被确认条或导航裁掉。
- `GoalDeckCardView`：上方 20px 保持较实的独立色块；下方沿露出边界渐隐。保留高光、阴影和轻微颗粒；当前决策是**取消卡片自身的磨砂玻璃效果**，使用 35% 透明的独立色块。背景磨砂只属于整体背景层。
- 所有可点控件至少 44pt 命中区；滑动必须有点击/按钮替代路径，方便无障碍和真机测试。
- 所有固定底部元素使用 `safeAreaInset` 或等效布局，不能用绝对坐标压住内容。

## 视觉与动效规则

1. 首页点击三张预览时：三张预览各自插入目标堆对应位置，不能只做整页淡入淡出。
2. 进入卡片堆：标题、日期、计数同步缩小并移动到内页位置；返回首页时逆向进行，不能闪动或突然消失。
3. 上下翻页：舒缓、连续，无大幅弹跳；快速连续操作也只能收敛到一个稳定焦点。
4. 右滑选择：卡片向右移，最多三张；不要将卡片移出屏幕。
5. 已选首页：仅单卡轮播，两侧小箭头为提示；首次冷启动不能显示“开始目标”。
6. 执行页：头部离场后再完成卡片扩展；提交按钮留在卡片右下且高于底部导航。
7. `accessibilityReduceMotion` 为真时：取消流体与空间移动动画，直接显示最终状态，但保留内容与状态变化。

## 数据接入分两步

### 第一步：仅 mock，先锁视觉

创建 `GoalRepository` 协议和内存实现，页面只依赖：

```swift
protocol GoalRepository {
    func availableGoals(for date: Date) async throws -> [Goal]
    func selectedGoalIDs(for date: Date) async throws -> Set<String>
    func saveSelectedGoalIDs(_ ids: Set<String>, for date: Date) async throws
    func submit(_ entry: GoalEntry) async throws
}
```

这一步不迁移 Drift、不改 Flutter 数据库、不接真实提交。

### 第二步：接真实规则

仅在 S1–S5 逐屏验收后，再决定以下两种路线之一：

1. 原生 SwiftData / SQLite 重建数据层，并用迁移脚本导入既有数据；或
2. 暂时继续由 Flutter / 原生桥接提供数据，等其余页面迁完再收口。

必须先确认用户是否需要保留已安装旧版 App 的本地数据，才可选择最终方案。
