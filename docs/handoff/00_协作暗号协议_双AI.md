# 协作暗号协议(大C ↔ 大D)

> 目的:大C(Claude,在用户 Windows 台式机)与大D(Codex,在用户 MacBook Pro)不直接对话,双方只在 GitHub 的 docs/ 文件夹里留话。用户只需要传一句暗号,不需要复制粘贴任何内容。

## 双方各自的读写位置(白板)

| 内容 | 谁写 | 固定位置 |
|---|---|---|
| 给大D 的工作指令 | 大C | `docs/handoff/给大D_*.md` + `docs/CURRENT.md` 顶部提示块 |
| 大D 的完成回复 | 大D | **固定文件 `docs/handoff/给大C_最新回复_大D.md`**(每次覆盖写,格式:已完成项/验证结果/遗留问题/最新提交号) |
| 大C 的复核结论 | 大C | `docs/reviews/NN_*.md`(流水号递增) |
| 双方分歧、需用户拍板的事 | 任一方 | 在对应文档里标一行"待用户拍板:…" |

## 触发暗号(用户传话用,一字不改)

**暗号 1 — 用户对大D 说**:
> 去 GitHub 分支 `feature/stage3-local`,先读 `docs/handoff/00_协作暗号协议_双AI.md`,再读 `docs/CURRENT.md` 顶部提示和 `docs/handoff/` 里最新的 `给大D_*.md` 指令,按它执行。完成后把回复写进 `docs/handoff/给大C_最新回复_大D.md` 并推送到该分支。

**暗号 2 — 用户对大C 说**:
> 去 GitHub 的 `feature/stage3-local` 读最新 `docs/reviews/` 复核列表,以及 `docs/handoff/给大C_最新回复_大D.md`(如果有),继续复核。

## 规矩

1. 每次开工先 `git fetch origin` 并读上述白板,不要凭记忆或本地旧文件判断。
2. 只改自己负责的文档和白板上约定的文件;不合并 main 除非用户/复核结论明确同意。
3. 回合以"大D 回复 → 大C 复核 → 用户真机验收 → 合并 main"为一个闭环。
4. 回复必须带最新提交号,方便确认看到的是哪一版。
