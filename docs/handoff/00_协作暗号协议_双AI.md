# 协作暗号协议(大C ↔ 大D)

> 目的:大C(Claude,在用户 Windows 台式机)与大D(Codex,在用户 MacBook Pro)不直接对话,双方只在 GitHub 的 docs/ 文件夹里留话。用户只需要说一句暗号"**去看看**",不需要复制粘贴任何内容。

## 暗号:去看看(唯一暗号,两边通用)

用户说"**去看看**"时,含义对双方都成立:

1. **先办用户交代的事**:用户说"去看看"之前交代的具体内容,最先执行(比如"修格子""合并 main""删调试按钮")。
2. **再去共同小黑板**:拉取 GitHub,看对方新留了什么,该执行执行、该复核复核。
3. 若用户没交代别的事,则"去看看"= 自己去把小黑板上的最新指令/最新回复处理完。

**大D 收到"去看看"的完整动作**(在 MacBook 项目目录):
先 `git fetch origin`,读 `docs/CURRENT.md` 顶部提示与 `docs/handoff/` 里最新的 `给大D_*.md`;按指令执行;完成后把回复(已完成项/验证结果/遗留问题/最新提交号)覆盖写到 `docs/handoff/给大C_最新回复_大D.md` 并推送 `feature/stage3-local`。

**大C 收到"去看看"的完整动作**(在 Windows 工作区):
先 `git fetch origin`,读 `docs/handoff/给大C_最新回复_大D.md`(若有新内容)与 `docs/reviews/` 新增复核;执行用户交代的事;把结论写进 `docs/reviews/NN_*.md` 及需要时的新 `docs/handoff/给大D_*.md`,一并推送。

## 双方各自的读写位置(白板)

| 内容 | 谁写 | 固定位置 |
|---|---|---|
| 给大D 的工作指令 | 大C | `docs/handoff/给大D_*.md` + `docs/CURRENT.md` 顶部提示块 |
| 大D 的完成回复 | 大D | **固定文件 `docs/handoff/给大C_最新回复_大D.md`**(每次覆盖写) |
| 大C 的复核结论 | 大C | `docs/reviews/NN_*.md`(流水号递增) |
| 双方分歧、需用户拍板的事 | 任一方 | 在对应文档里标一行"待用户拍板:…" |

## 规矩

1. 每次开工先 `git fetch origin` 并读白板,不要凭记忆或本地旧文件判断。
2. 只改自己负责的文档和白板上约定的文件;不合并 main 除非用户/复核结论明确同意。
3. 回合以"大D 回复 → 大C 复核 → 用户真机验收 → 合并 main"为一个闭环。
4. 回复必须带最新提交号,方便确认看到的是哪一版。
